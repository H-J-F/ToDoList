# 构建与本地发布

## 职责

每轮文件修改结束后发布可运行程序到项目根目录 Build，并保持源码版本、程序集、关于页与目录名一致。需要 Windows、Git、Python 3 和 `global.json` 对应的 .NET 10 SDK；首次还原需要可访问 NuGet 或已有包缓存。

## 入口

```bat
Build.bat
Build.bat --version 2.4.0
Build.bat --force
```

[Build.bat](../Build.bat) 支持双击或任意工作目录调用，透传退出码；[Build.py](../tools/Build.py) 编排整个流程；[Publish.ps1](../tools/Publish.ps1) 发布两版；[Verify-Build.py](../tools/Verify-Build.py) 校验交付文件、许可证哈希与精简版体积。[Keeper](../.codex/项目管家/keeper.py) 检查文档并刷新索引。

## 契约

- [Directory.Build.props](../Directory.Build.props) 是产品版本唯一来源。默认按 `major.minor.patch` 的 patch +1，例如 2.3.1 → 2.3.2。用户指定版本时用 `--version`，原样采用合法三段数字版本。关于卡片与标题读取程序集版本。
- “每次修改”按一次完成并发布的改动计算，不按保存文件或工具调用次数递增。成功发布后无新改动再次运行直接跳过；`--force` 强制重建未修改源码且保持版本。
- `artifacts/keeper/build-state.json` 保存最近成功发布的文件哈希和输出位置。失败保留 pending 版本，修复后重试仍使用该版本；进程退出自动释放文件锁，防止并发递增。
- 如果删除了整个缓存，首次运行重新以当前版本 +1 建立基线；需保留原版本重建时使用 `--version`。仅删除索引 SQLite 不影响发布基线。
- 默认输出 `Build/ToDoList-<版本>-win-x64-lite` 和 `portable`。已有同名目录时，使用 `Build/rebuild-<版本>-<随机标识>/`，不覆盖、不清空已有安装和 Data。准确输出以 `Build/latest.json` 为准。
- 构建前后比对源码哈希，构建期间若发生新改动则拒绝标记成功。只有文档结构、Python 回归、解决方案编译、.NET 测试和两版包校验全部成功，才更新 latest 和基线。
- 每次实际构建使用独立的 `artifacts/build/<标识>` 中间目录，编译、测试和发布共用该目录，避免已运行的开发版锁住默认 bin 中的 DLL；不终止现有进程。
- README 的当前版本及包目录随构建同步；历史验收报告不改版本。Lite 依赖已安装的 Desktop Runtime，整个交付目录低于 50,000,000 字节；Portable 自带运行时并生成单 EXE。两版均包含许可证材料，不创建 ZIP、不做远程发布。

## 验证

运行 `Build.bat` 并确认退出码为 0。Python 测试覆盖自动递增、指定版本、失败重试、变更检测和 hook 输出；.NET 测试覆盖现有规则与存储行为。可用 `python tools/Verify-Build.py <latest中output路径> --allow-dirty --version=<版本>` 复查包。

本地工作区允许未提交修改；BUILD.json 仍如实记录 WorkingTreeDirty。不要把构建通过描述为全部 UI 验收通过。失败日志见控制台，Stop 触发的日志见 `artifacts/keeper/stop-build.log`；失败包不会写入 latest，修复后直接重跑。

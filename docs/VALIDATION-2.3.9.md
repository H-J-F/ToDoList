# 2.3.9 托盘、设置与笔记切换验收

## 问题与实现

- 托盘改用 WPF-UI.Tray 4.3.0，保留现有 Fluent 菜单、双击恢复与笔记提示。退出获准后，在 Dispatcher 和输入线程仍可用时关闭弹窗、释放鼠标捕获，并释放注册时记录的本实例 HwndSource；随后关闭主窗口与应用。没有使用强制结束进程或禁用全局触摸来实现产品退出。
- 实际鼠标基线复现：选择减少动态效果已经保存，但设置面板把下拉弹窗点击判为外部点击并折叠。证据为 `artifacts/fixes239/baseline-check2/settings-navigation.json`。修复跨 Popup 的逻辑归属识别；设置同步独立于导航，并采用稳定模板、延迟合并保存与失败回滚。
- 笔记切换的全工作区高不透明度遮罩被移出该流程；目标笔记数据准备完毕后统一提交。标准模式在新内容上淡出旧快照 150ms，减少动态效果时直接更新，失败保留原笔记。

## 开发验证证据

`artifacts/fixes239/settings-navigation-full4/settings-navigation.json` 的 Completed、Passed 均为 true。覆盖实际鼠标和键盘的标准→减少→换肤→标准操作链、字号／密度、连续选择、设置文件锁定时回滚、恢复保存、动画中断后重开、两种模式下有任务／空笔记切换、350ms 人为延迟加载、损坏数据库失败、取消未保存草稿切换，以及操作之后的实际托盘右键退出。相邻 PNG 为 WPF 渲染的切换帧，JSON 保存遮罩、快照与透明度状态。

`artifacts/fixes239/tray-native12/lifecycle.json` 与 `tray-native13/lifecycle.json` 分别记录标准和减少模式下，实际右键打开系统托盘图标、再次打开菜单、实际鼠标点击退出、注销图标及释放消息源。测试进程退出码为 0。

开发期间若测试发生输入干扰或菜单事件未送达，保留失败报告，不计为成功。早期一个等待人工输入的隔离测试进程按 PID 和 artifacts 可执行路径核实后清理；清理不属于退出验收证据。批量测试检测到用户鼠标位置变化后，已协调独占输入时间。

## 发布包验收方法

分别运行 `python -X utf8 tools/Verify-Lifecycle.py <Lite/Portable 的 ToDoList.exe>`，以各轮 artifacts/lifecycle/<标识>/process-exit.json 的 Passed 为准。12 个场景覆盖显示／隐藏、两种动画模式、辅助隐藏窗口、取消／保存失败、草稿保存／放弃、重启、完整设置与笔记流程及设置重启持久化。每个场景保留独立结果，复用数据目录的重启不会覆盖首轮归档。

普通托盘场景、草稿入口与设置之后退出使用真实系统鼠标输入；辅助隐藏窗口场景使用实际菜单的程序性 Click 事件。弹窗中的保存／放弃／取消决策及错误注入使用程序性操作。切换 PNG 是 WPF 视觉树渲染，不是屏幕录像。

外部程序观察到关闭报告后等待最多 5 秒，要求进程结束、退出码为 0 且界面断言通过。窗口 Closed、应用 OnExit 或图标注销单独出现均不代表进程验收成功。Build.bat 的文档结构检查与包校验也不能替代这些语义验收。
